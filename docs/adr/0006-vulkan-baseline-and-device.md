# 0006. Vulkan baseline, bindings and device selection

- Status: Accepted
- Date: 2026-09-25
- Research: [docs/research/vulkan-baseline.md](../research/vulkan-baseline.md)

## Context

CLAUDE.md §6 fixes Vulkan 1.3 through `ash` with a thin `engine_rhi`, and leaves two things to an
ADR: the minimum GPU tier, and how devices are chosen. The user asked for the widest hardware
reach (integrated to discrete; NVIDIA and AMD first, Intel supported), which means Vulkan 1.3 as
the floor and 1.4 used opportunistically.

## Options

- **Floor:**
  1. Vulkan 1.3 core only;
  2. Vulkan 1.3 plus the bindless and GPU-driven feature set (chosen);
  3. Vulkan 1.4.

  Option 1 would force non-bindless fallback paths. Option 3 excludes GPUs whose Windows drivers
  stopped at 1.3.
- **Bindings:**
  1. ash 0.38 (chosen);
  2. ash from git;
  3. bindings generated by us from `vk.xml`.

  Git dependencies are denied by cargo-deny, and our own generator is work we do not need yet.
- **Adapter choice:**
  1. first discrete (Wicked);
  2. scoring by kind, then device-local memory, with an environment override (chosen).

## Decision

- **Required on every GPU.** Vulkan 1.3 plus:
  - `dynamicRendering`, `synchronization2`, `maintenance4`;
  - `timelineSemaphore`, `bufferDeviceAddress`;
  - descriptor indexing: `descriptorIndexing`, runtime arrays, partially bound, variable
    count, update-after-bind for sampled images, storage images and storage buffers;
  - non-uniform indexing of sampled images, storage images and storage buffers;
  - `scalarBlockLayout`, `shaderDrawParameters`, `samplerAnisotropy`.

  An adapter lacking any of them is listed with the missing names, and the error names them all.
- **Optional, detected and reported** (`OptionalCaps`), enabled when a feature needs it:
  - mesh shaders, ray tracing, descriptor buffer, graphics pipeline library;
  - pipeline binary, present wait/id;
  - `VK_NV_low_latency2`, `VK_AMD_anti_lag`;
  - device fault, calibrated timestamps.

  Extensions newer than ash's headers are detected by name.
- **Selection.** Discrete GPUs come first, then integrated, virtual and CPU, with the larger
  device-local heap winning ties. `ENGINE_ADAPTER` overrides the preference: `high-performance`,
  `low-power` or a name substring.
- **Queues.** A graphics queue on a graphics+compute family, an async-compute queue on a
  compute-only family if the GPU has one, and a transfer queue on a transfer-only family if it
  has one.
- **Validation.** It is on by default in debug builds when the Khronos layer is installed. A
  messenger counts errors and warnings, and tests assert zero errors.
- **Loading.** `ash` with `loaded`: a missing driver is an error value (`RhiError::Loader`),
  not a crash at start-up.
- **Tests:**
  - lavapipe in development containers;
  - skip-with-note on hosted CI without a GPU;
  - `ENGINE_REQUIRE_GPU=1` on the GPU workflow, which runs on ref-1 on NVIDIA and on the AMD
    iGPU.

## Measurements

- `tests/gpu.rs::offscreen_triangle`: a Slang triangle rendered with dynamic rendering,
  synchronization2 barriers and a timeline semaphore, then read back and pixel-checked.
  The centre pixel is `[150, 119, 100, 255]` on all three implementations, with **0 validation
  errors and 0 warnings**:

  | Implementation | Validation layer | Queues (graphics / async compute / transfer) |
  |---|---|---|
  | Mesa lavapipe 25.2.8 (container) | 1.3.275 | family 0 / – / – |
  | ref-1 NVIDIA RTX 4060 Ti, driver 616.92, Vulkan 1.4.351 | SDK 1.4.350 | 0 / 2 / 1 |
  | ref-1 AMD Radeon iGPU, driver 25.10.36, Vulkan 1.4.315 (`ENGINE_ADAPTER=radeon`) | SDK 1.4.350 | 0 / 1 / 2 |

  ref-1 numbers are from the GPU workflow on commit `c0d77f0`.
- **Scoring by kind first is necessary.** The AMD iGPU reports 22.6 GiB of device-local
  memory (shared system RAM), more than the RTX 4060 Ti's 15.7 GiB. Ranking by memory alone
  would have picked the iGPU.
- The AMD iGPU does not expose `VK_EXT_mesh_shader`; the RTX does. Mesh shading therefore
  needs a fallback path (already planned, §6).
- The minimum-tier consequence (which GPU generations pass the required set) must still be
  checked against gpuinfo.org, which is not reachable from the development container. This is
  noted as a follow-up.

## Consequences

- Rendering code can assume bindless and BDA everywhere; no fallback paths.
- GPUs with only Vulkan 1.2 drivers (for example pre-Maxwell NVIDIA, or pre-Polaris AMD on
  Windows) are unsupported and get a clear error.
- Missing ash definitions for new extensions are added locally in `engine_rhi` when used.
- The memory allocator (gpu-allocator or our own) is decided in the ADR that introduces
  buffers and textures. The offscreen test allocates dedicated memory directly.
