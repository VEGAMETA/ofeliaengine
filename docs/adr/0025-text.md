# 0025. Text: own layout on HarfRust and skrifa, bitmap glyph atlas

- Status: Accepted
- Date: 2026-09-26
- Research: [docs/research/text.md](../research/text.md)

## Context

The editor, the in-game UI and the debug overlays all draw text (CLAUDE.md §12, §13).
The editor alone lays out thousands of labels (inspector fields, hierarchy rows, console
lines) and relays them on every resize or edit, and its input response must stay within a
frame (§12).

Text must:
- shape correctly (kerning, ligatures, any script HarfBuzz supports);
- break lines by UAX #14 and handle bidi when needed;
- fall back to other fonts;
- render crisply at UI sizes and scale in the world.

## Options

1. **Parley** (Linebender): full rich-text layout on HarfRust, skrifa, fontique and
   ICU4X.
   - Correct and general.
   - Measured at 5.9 µs per short label and 1.3 ms for a 10 KB paragraph; 80 crates on
     Windows.
2. **cosmic-text:** similar scope. Faster than Parley on labels, 2× slower on
   paragraphs. Pins old HarfRust and skrifa.
3. **Our own layout on HarfRust + skrifa** (chosen):
   - `unicode-linebreak` for UAX #14 and `unicode-bidi` when needed;
   - the sketch measured 1.0 µs per label and 193 µs per paragraph, with identical glyphs.

## Measurements

`bench/text-compare`, dev container (not reference hardware; ref-1 numbers from the
Bench workflow are added to `docs/perf/history.md`). Go Regular 14 px, from bytes.

| Scenario | Parley 0.11.1 | cosmic-text 0.19.0 | `engine_text` |
|---|---:|---:|---:|
| 1,000 labels, shape + lay out | 6,254 µs | 6,256 µs | **1,399 µs** (4.5× faster than Parley) |
| 10 KB paragraph, shape + wrap at 600 px | 1,222 µs | 2,521 µs | **265 µs** (4.6× faster than Parley) |
| Glyphs / lines (check) | 22,570 / 84 | 22,570 / — | 22,570 / 84 |

Two changes brought `engine_text` from 2.5 µs to 1.4 µs per label and from 776 µs to
265 µs per paragraph:
- a 128 KiB glyph table for the Basic Multilingual Plane, built at font load, instead of a
  charmap search for every character outside ASCII;
- table-free script detection for ASCII, Latin-1 and Cyrillic.

`cargo bench -p engine_text` (same container):
- rasterizing a glyph: 2.1 µs at 14 px, 4.2 µs at 48 px;
- atlas lookups of cached glyphs: 11 ns per glyph;
- `tests/zero_alloc.rs`: layout and atlas lookups over 540 frames make 0 allocations.

**ref-1** (Ryzen 7 7700, Bench workflow run 36233750530, commit 2ec43f7):

| Scenario | Parley 0.11.1 | cosmic-text 0.19.0 | `engine_text` |
|---|---:|---:|---:|
| 1,000 labels, shape + lay out | 4,509 µs | 4,993 µs | **872 µs** (5.2× faster than Parley) |
| 10 KB paragraph, shape + wrap at 600 px | 907 µs | 2,017 µs | **170 µs** (5.3× faster than Parley) |

- Rasterizing a glyph takes 1.18 µs at 14 px and 2.18 µs at 48 px.
- Atlas lookups of cached glyphs take 6.2 ns per glyph.

## Decision

**`engine_text`, platform-independent:**

- **Fonts:**
  - `Font` from bytes: skrifa for metrics, charmap and outlines; HarfRust `ShaperData`;
    shape plans cached per script and direction.
  - A font stack (`&[FontId]`): a primary font and fallbacks; the first font with the
    glyph wins.
- **Layout (`TextLayout`, reusable buffers):**
  - itemize by script and font;
  - shape each run;
  - UAX #14 break opportunities; greedy wrapping with hanging whitespace and mandatory
    breaks;
  - alignment (start, center, end) and line metrics.
  - Right-to-left runs (Arabic, Hebrew, ...) are shaped right to left and placed in visual
    order. Full UAX #9 reordering (`unicode-bidi`) for mixed-direction paragraphs comes
    later, with the editor's text input.
  - Output: positioned glyphs and lines.
- **Rasterization:**
  - our own coverage rasterizer over skrifa outlines (signed-area accumulation);
  - glyph bitmaps keyed by (font, glyph, size in 1/64 px, subpixel x in quarter pixels);
  - a shelf-packed R8 atlas with dirty rectangles for the GPU upload;
  - LRU eviction by frame, cleared when full.
- **Rendering:** the 2D renderer draws glyphs as quads from the atlas. Text and UI render
  into their own premultiplied target
  ([frame generation requirements](../research/frame-generation.md)).
- **Dependencies, all MIT or Apache-2.0:**
  - `harfrust` 0.13.3 and `skrifa` 0.46 (one `read-fonts` 0.43);
  - `unicode-linebreak` 0.1.5;
  - `unicode-script` 0.5.8 for itemization (`unicode-bidi` 0.3.18 joins with full bidi).

## Consequences

- **The common case is several times faster than general libraries,** so UI text can be
  laid out per frame when needed. The editor still caches layouts per widget.
- **We own correctness beyond shaping** (itemization, breaking, bidi, fallback). Parley in
  `bench/text-compare` is the reference for glyph and line counts in tests.
- **Not in the first version:**
  - rich text (several styles in one layout; the API takes a single style for now);
  - system font fallback on Windows (DirectWrite), for CJK and emoji in the editor;
  - MSDF for world-space text;
  - dictionary-based line breaking (Thai and others).
  - Each comes when a consumer needs it.
