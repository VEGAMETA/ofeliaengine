# 0022. Reflection: static field tables with offsets

- Status: Accepted
- Date: 2026-09-26
- Research: [docs/research/reflection.md](../research/reflection.md)

## Context

Four subsystems need to see inside components:
- text serialization of scenes and settings (§13);
- the editor's inspector (§12);
- Luau property access and `.d.luau` generation (§10);
- network replication with per-field quantization (ADR 0019).

The replication path touches thousands of entities per tick, so field access must be
cheap. Script-defined components must be described the same way as Rust ones.

## Options

1. **`bevy_reflect`.** Complete, but field access is dynamic dispatch per field, and it
   pulls Bevy's type registry and serde.
2. **Godot-style properties.** Named get/set through a variant type: a string lookup and
   a conversion on every access.
3. **Unreal-style static property tables with offsets,** generated by a derive
   (chosen).

## Decision

- **`engine_reflect`:**
  - `TypeInfo`: a name, size, alignment and a kind:
    - a primitive;
    - a struct: fields with name, offset, type, attributes;
    - a C-like enum with a `repr`;
    - a fixed array;
    - or opaque.
  - `#[derive(Reflect)]` (`engine_reflect_derive`, on the syn 3 already in the build)
    generates it with `offset_of!`. It handles named and tuple structs and C-like enums.
- **Attributes, one namespace:**
  - `min`, `max` (writes through reflection clamp);
  - `step`, `tooltip`, `hidden`, `skip`;
  - `net_quantum`, `net_skip`;
  - `hint` (`color`, `degrees`, `multiline`);
  - `rename` (stable names in files).
- **Access:**
  - `TypeInfo::path("position.x")` resolves to an offset, type and attributes;
  - `read` / `write` convert between numeric kinds, saturate, clamp, and refuse
    non-variants of enums;
  - `get` / `set` are the safe typed forms;
  - `visit_leaves` lists every primitive in declaration order, for serialization and
    network field lists.
- **Math types** (vectors, quaternion, matrix) have hand-written tables. SIMD types are
  described by their layout, which a test checks.
- **ECS:**
  - `Component::TYPE_INFO` carries the description, set by
    `reflect_component!(pod Health)`;
  - `ComponentDesc::type_info` lets script components pass one built at run time;
  - `Entity`, `Parent` and `Children` are described; hierarchy links are hidden from
    the inspector.

## Measurements

Reading a field is an offset add and an unaligned load, with no allocation or dynamic
dispatch. A benchmark follows with the first consumer, the network snapshot encoder or
the serializer.

Tests:
- derived descriptions match `offset_of!`;
- attributes, renames and enum variants;
- path reads and writes with clamping, saturation and variant checks;
- leaf order and offsets;
- SIMD math layouts;
- reflected ECS components read through `World::get_raw` plus the field offset.

## Consequences

- **Serialization** (ADR to follow) writes and reads through `visit_leaves` and `path`.
  The text format is the team's decision (research note).
- **The editor inspector** builds widgets from `TypeKind`, `Attrs` and `Hint`.
- **The Luau bindings generator** reads the same tables.
- **Not supported yet:** generic types, `Vec` and maps. Such components are opaque to
  reflection until a serialization hook exists.
